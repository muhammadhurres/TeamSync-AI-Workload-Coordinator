System Data Flow

When a team coordinator clicks "Generate Balanced Schedule", data travels through three clean stages:

Trace the Core Path (Code Route)

1
static/app.js → handleCoordinate()

Scrapes member and task inputs from the HTML table, runs empty checks, and sends a POST request to /api/coordinate.

2
security.py → CoordinationRequest

Pydantic enforces max 10 members, max 20 tasks, strips control characters, and blocks prompt injection markers before the data hits any LLM.

3
coordinator.py → coordinate_tasks()

Dispatches the payload to OpenRouter (Qwen 2.5 Coder or LLaMA 3.3) with regex fallback parsing, or executes the deterministic offline mock engine.

4
static/app.js → animateCountUp() & renderAssignments()

Receives the verified response, scrolls to the results view, triggers the numeric count-up animation for the fairness badge, and renders safe task cards.

To Change This, Start Here

Change or add preset sample hackathon data

Edit SAMPLE_MEMBERS and SAMPLE_TASKS in static/app.js.

Swap AI models or adjust temperature

Look at PRIMARY_MODEL and FALLBACK_MODEL at the top of coordinator.py.

Tweak the color theme or kinetic speeds

Modify CSS custom properties (--ochre-primary, --cyan-accent) and @keyframes in static/style.css.

A Practice to Reuse

The Dual-Mode Resilience Pattern: By coupling our live OpenRouter API call with an intelligent local mock engine (coordinator.py:mock_coordinate), the application never becomes fragile during live presentations, video recordings, or rate limits.

Specifying strict Pydantic schemas upfront prevented prompt variations from crashing the client and allowed frontend and backend to integrate on the first run without friction.
